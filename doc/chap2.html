2 Functionality

This chapter lists all functions contained in the IdPGroup package.

2.1 Identifying groups via a search tree

This section briefly describes the functions and variables of this package associated with the identification of an arbitrary group of order 512 via a search tree. For further informations see [ES26].

By 'identify' a group G, we mean that we want to find an id such that SmallGroup(512, id) is isomorphic to G. This is done by calculating invariants and comparing them with the ones of the remaining candidates. This process is organized in the tree ID_GROUP_512_TREE (2.1-3). The tree used is implemented as nested records with the following components:

  • "fp": a list of integers, each being the encoded fingerprint of groups resulting from the specific test performed at the current level of the identification routine.

  • "next": a list comprised of the respective subbranches corresponding to the fingerprints in "fp". This is either a list of ids or a branch implemented as a record itself.

Depending on the depth in the tree, each record also has one of the following two components:

  • "test": a string that indicates which test was used via TestOnGroup (2.4-3) to create the listed fingerprints.

  • "desc": a list of integers that encode a description of the performed powermap-test.

The first levels of ID_GROUP_512_TREE (2.1-3) try to distinguish groups by the following invariants:

  • the rank of the group,

  • the collected orders of all elements of the group,

  • the numbers of conjugacy classes of each length and representative order (the order of the elements in the class) of the group,

  • the isomorphism type of the parent of the group, i.e. the quotient of the group and the smallest non-trivial element of the lower-p-central series,

  • the abelian invariants, i.e. the isomorphism types of the factor groups of the derived series of the group G and

  • the cycle structure of the permutations induced on all clusters of conjugacy classes of same length and representative order by the power map x\mapsto x^3.

If necessary, these invariants are followed by invariants resulting from power maps evaluated on partitions of G. The initial partition is made of the conjugacy classes of G grouped such that conjugacy classes of the same length and same representative order belong to the same partitioning subset. The collected result of a power map applied to a subset forms an invariant used to distinguish groups in these levels of the search tree. The describing parameters (e.g. which subset and power map) are determined by the content of the component "desc". After the evaluation, the partition is refined according to the respective result. If the preceding invariants do not lead to a single group, the following (more time consuming) invariants are calculated:

  • the isomorphism types of maximal factors formed by factoring out subgroups generated by elements of the smallest non-trivial subgroup in the lower-p-central series,

  • the isomorphism types of maximal factors formed by the group and central subgroups and

  • the isomorphism types of all maximal subgroups.

After this process, 139 pairs and 1 triplet of groups remain unidentified. These groups are distinguished by a random isomorphism test, the same way ultimately used in the SmallGrps library for the groups of order 256, for more details see [BE99].

2.1-2 IdGroup512
‣ IdGroup512( G[, opt] )( function )

Returns: Integer id such that SmallGroup(512, id) is isomorphic to G.

Identifies the group G of order 512. This function accepts a record opt of options with the following content:

  • path: a boolean that determines if the path through the tree shall be recorded while identification and returned as well.

  • tree: a search tree that was built using the invariants resulting from tests.

  • anupq: a boolean that determines if IsPqIsomorphicPGroup from the Anupq-Package is used to find the group isomorphic to G among the remaining candidates.

gap> G := Image(IsomorphismPermGroup(SmallGroup(512, 1984)));;
gap> IdGroup512(G);
1984
gap> IdGroup512(G, rec(path := true));
[ 1984, rec( fp := [ 2, 8217, 5321 ], pos := [ 2, 188, 1 ],
        tests := [ "Rank", "ElmOrds", [ 40511009 ] ] ) ]
gap> H := Image(IsomorphismPermGroup(SmallGroup(512, 449)));;
gap> IdGroup512(H, rec(anupq := false));
449
gap> IdGroup512(H, rec(anupq := true));
449

2.2 Loading (strong) siblings

This section describes the functions used to load precalculated lists of (strong) siblings, i.e. groups satisying the following definitions:

  • subgroup-equivalent groups are groups with a bijection between the sets of proper subgroups s.t. preimage and image are isomorphic,

  • factor-equivalent groups are groups with a bijection between the sets of proper factors s.t. preimage and image are isomorphic,

  • siblings are subgroup- and factor-equivalent groups, where the bijection of proper subgroups preserves conjugacy and maps the Frattini subgroup, lower and upper central series onto the respective counterparts,

  • strong siblings are siblings that are also Brauer Pairs.

All (strong) siblings of orders dividing 512 together with some trivial cases are implemented in this package, and are callable by the following functions.

2.2-1 Siblings
‣ Siblings( order, justids[, indices] )( function )

Returns: A list of lists of siblings of size order. The parameter justids determines wether the ids or the groups (default) shall be returned.

If available, loads and returns a list of siblings of size order. Currently available sizes are:

  • all orders of the form p\,q for p and q primes,

  • all powers of 2 up to 2^9,

  • all powers of 3 up to 3^6,

  • all powers of a prime up to p^4 and

  • all orders smaller than 256 except 60, 120, 160, 168, 180, 189, 192 and 240.

If no list is available for the provided order, fail is returned. If a list indices is given, only the respective entries are returned.

gap> Siblings(101);
[ ]
gap> Siblings(128);
[ [ <pc group of size 128 with 7 generators>,
    <pc group of size 128 with 7 generators> ],
  [ <pc group of size 128 with 7 generators>,
    <pc group of size 128 with 7 generators> ],
  [ <pc group of size 128 with 7 generators>,
    <pc group of size 128 with 7 generators> ] ]
gap> Siblings(128, true);
[ [ 1317, 1322 ], [ 1327, 1329 ], [ 1597, 1598 ] ]
gap> Siblings(256, true, [1..3]);
[ [ 227, 228 ], [ 258, 260, 261 ], [ 845, 846 ] ]

2.3-2 CalculateSiblings
‣ CalculateSiblings( order )( function )

Returns: A list of lists of ids of groups of size order that are siblings.

Determines all siblings among the groups of size order by applying the tests "MaxSubId", "SpSubId", "SubId", "MaxFactId" and "FactId" iteratively. The tests "MaxSubId" and "MaxFactId" are not necessary, but are efficient and eliminate some sets before applying the more costly tests.

2.4 Functions for building a search tree

This section describes all functions and variables connected to building a search tree that can be used with IdGroup512 (2.1-2) to identify groups via implemented invariants.

In short, this is done by initializing a tree via calling TestOnClusterList (2.4-4) with a selected test on a list of ids of groups of given order and then iterating the following three steps:

  • collecting the clusters of the current tree via ClusterList (2.4-2),

  • performing a chosen test on these clusters via TestOnClusterList (2.4-4) and

  • extending the tree with these test results via AddClusterTestResults (2.4-5).

A very effective set of invariants can be obtained by calling CocTestOnClusterList (2.4-7) in the second step. This should only be done when the groups of each provided cluster yield the same value when the test CocList is applied. Furthermore these invariants should be used for as few as possible clusters since CocTestOnClusterList (2.4-7) includes a search for suitable parameters that can take quite some time.

2.4-2 ClusterList
‣ ClusterList( tree )( function )

Returns: A list of all clusters of groups in tree (i.e. the leaves of tree).

Iterates through tree and collects information about each leaf as a record. This includes the size of the leaf, the path through tree leading to the leaf, the tests performed including descriptions of performed power map tests and the ids of the groups contained in the leaf.

gap>            rec( fp := [ 11744, 86646 ], next := [ [ 5 ], [ 6, 7 ] ],
gap>                test := "MaxSubId" ) ], test := "ElmOrds" );;
gap> ClusterList(tree);
[ rec( descl := [  ], ids := [ 3, 8 ], path := [ 63049 ], size := 2,
       tests := [ "ElmOrds" ] ),
  rec( descl := [  ], ids := [ 4 ], path := [ 75721 ], size := 1,
       tests := [ "ElmOrds" ] ),

2.4-3 TestOnGroup
‣ TestOnGroup( G, test[, opt] )( function )

Returns: The result of test applied to G, if desired encoded as an integer.

Calculates an invariant of the group G. The following choices for test are implemented:

  • "ElmOrds": the collected orders of the elements of G,

  • "Center": the abelian invariants of the center of G,

  • "Rank": the rank of G,

  • "AbelInv": the order and abelian invariants of each term in the derived series of G,

  • "UCSId": the isomorphism types of the proper subgroups in the upper central series of G via IdGroup,

  • "LCSId": the isomorphism types of the proper subgroups in the lower central series of G via IdGroup,

  • "PCSId": the isomorphism types of the proper subgroups in the p-central series of G via IdGroup,

  • "SpSubId": the isomorphismtypes of the Frattini subgroup, the terms in the #! upper and lower central series of G via IdGroup,

  • "MaxSubId": the collected isomorphism types of all maximal subgroups of G via IdGroup,

  • "SubId": the sizes and collected isomorphism types of conjugacy classes of all proper subgroups via IdGroup,

  • "MaxFactId": the collected isomorphism types of all maximal factors of G via IdGroup,

  • "CentQuot": the collected isomorphism types of all quotients of G with subgroups generated by non-trivial central elements of G via IdGroup,

  • "LCSFactId": the collected isomorphism types of all quotients of G with cyclic subgroups generated by non-trivial elements of the last non-trivial term of the p-central series,

  • "FactId": the collected isomorphism types of all proper factors of G via IdGroup,

  • "CocList": the collected numbers of conjugacy classes of G of same length and same representative order (the order of a representative),

  • "PMCycSt": the cycle-structure of the permutation induced by the power map x\mapsto x^3 on the collected conjugacy classes,

  • "fpfunc": Uses the function provided as opt.fpfunc.

This function accepts a record opt of options consisting of the boolean opt.pack, that determines if the result of a test should be encoded as an integer, and opt.fpfunc a costume function.

gap> G := SmallGroup(512, 1405);;
gap> TestOnGroup(G, "ElmOrds");
85416
gap> TestOnGroup(G, "ElmOrds", rec(pack := false));
[ [ 1, 1 ], [ 2, 7 ], [ 4, 24 ], [ 8, 288 ], [ 16, 64 ], [ 32, 128 ] ]

2.4-4 TestOnClusterList
‣ TestOnClusterList( CL, test[, opt] )( function )

Returns: Either a list of pairs each containing the path to the respective cluster (which is a leaf of a search tree) and the subbranch resulting from the results of test, or just the list of subbranches if CL contains only lists of integers. If CL consists of a single list of integers, the single resulting subbranch is returned on its own.

Performs the chosen test on the groups of each record in the CL. The tests are performed by TestOnGroup (2.4-3). CL could either be a list of records produced by ClusterList (2.4-2) or be a list of lists containing ids. In the former case, the output is a list of pairs containing the path of a cluster and the subbranch resulting from the test. In the latter case, only a list of subbranches is returned. If in the latter case, the returned list only contains one subbranch, the subbranch itself is returned. This is useful when building the first level of a search tree. This function accepts a record opt of options with the following content:

  • pack: A boolean that is handed to TestOnGroup (2.4-3).

  • ign1cl: A boolean that determines if clusters of size 1 should be ignored.

  • order: An integer giving the order of the groups with ids in CL.

  • notetest: A boolean that decides if the performed test should be noted in the returned subbranches. If so, subbranches that do not split a cluster are omitted.

gap> TestOnClusterList([[1..10]],"ElmOrds");
rec( fp := [ 88570, 4310, 63049, 75721 ],
     next := [ [ 1 ], [ 2, 5, 6, 7, 9, 10 ], [ 3, 8 ], [ 4 ] ],
     test := "ElmOrds")
gap> TestOnClusterList([[1,2,5],[7,8,9]],"ElmOrds");
[ rec( fp := [ 88570, 4310 ], next := [ [ 1 ], [ 2, 5 ] ],
       test := "ElmOrds" ),
  rec( fp := [ 4310, 63049 ], next := [ [ 7, 9 ], [ 8 ] ],
       test := "ElmOrds") ]
gap> tree := TestOnClusterList([[3..8]],"ElmOrds");;
gap> CL := ClusterList(tree);
[ rec( descl := [  ], ids := [ 3, 8 ], path := [ 63049 ], size := 2,
       tests := [ "ElmOrds" ]),
  rec( descl := [  ], ids := [ 4 ], path := [ 75721 ], size := 1,
       tests := [ "ElmOrds" ]),
  rec( descl := [  ], ids := [ 5, 6, 7 ], path := [ 4310 ], size := 3,
       tests := [ "ElmOrds" ]) ]
gap> TestOnClusterList(CL, "MaxSubId", rec(notetest := false));
[ [ [ 63049 ], rec( fp := [ 62603 ], next := [ [ 3, 8 ] ] ) ],
  [ [ 4310 ], rec( fp := [ 11744, 86646 ], next := [ [ 5 ], [ 6, 7 ] ] ) ] ]

2.4-8 ParametersRandPresentTest
‣ ParametersRandPresentTest( CL, order, maxl )( function )

Returns: A list consisting of pairs of a list of ids and a record containing the parameters for a random presentation test via ID_GROUP_FUNCS[18] defined in the SmallGrps package.

Determines the needed parameters for the groups of size order in the clusters cl of CL. Creates the clusters of conjugcy classes and alters them accordingly to the cl.descl. Afterwards minimal generators for all groups are chosen and their position among the clusters of conjugacy classes are determined. If the positions do not coincide, the positions of the generators of the first group are selected and the generators of the other groups are selected from the same clusters. Otherwise the positions and generators are sorted by the positions. Sequently the function tries to refine the corresponding clusters to limit the choices to choose from and repeat the process until either the number of refinments is equal or larger than maxl or no more refinments could be found.

gap> ParametersRandPresentTest([rec(descl:=[], ids:=[1367, 1371])], 512, 0);
[ [ [ 1367, 1371 ], rec( descl := [  ],
     fp := [ 39080, 80814 ], func := 18, pos := [ 8, 10 ] ) ] ]
gap> ParametersRandPresentTest([rec(descl:=[], ids:=[1367, 1371])], 512, 1);
[ [ [ 1367, 1371 ], rec( descl := [ 106003 ],
     fp := [ 39080, 80814 ], func := 18, pos := [ 9, 11 ] ) ] ]
